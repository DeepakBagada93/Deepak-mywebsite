# n8n Production Hardening Pack

Your workflow works in testing and dies quietly in production. This kit audits an exported n8n workflow for the failure modes that only show up under real traffic — then applies the safe fixes and blocks the rest in CI.

## What it catches

- Inline API keys, tokens, and embedded credential data (blocking, never auto-rewritten)
- Missing error workflow (failed runs fail silently)
- Unauthenticated webhooks
- HTTP calls with no timeout, and network/database/mail nodes with no retry policy
- Webhook-driven writes with no duplicate guard
- Pinned customer data left in the export
- Orphaned and disabled nodes that hide drift

## What's in the box

```
skills/workflow-hardener/
  SKILL.md                     # audit → triage → safe hardening → manual fixes → verify → handoff
  scripts/
    lib.mjs                    # workflow parser + rule engine
    audit-workflow.mjs         # JSON + Markdown findings, deterministic order
    harden-workflow.mjs        # four safe transform classes only; refuses on inline secrets
    verify-workflow.mjs        # CI gate (standard or --strict)
examples/
  lead-intake.workflow.json    # deliberately unsafe (12 findings, score 21/100)
  orders-sync.workflow.json    # half-hardened (3 findings, score 85/100)
  lead-intake-clean.workflow.json  # hardened reference (0 findings)
  expected/                    # real audit + hardened outputs, generated by the scripts
tests/workflow-hardener.test.mjs
```

## Requirements

- Node.js 18+ (verified on Node 25.9.0)
- An exported n8n workflow JSON. No n8n instance, API key, or network call is required to audit.

## First successful run (2 minutes)

```bash
cd n8n-hardening-pack

# 1) Audit the unsafe fixture
node skills/workflow-hardener/scripts/audit-workflow.mjs examples/lead-intake.workflow.json --md /tmp/audit.md

# 2) Confirm the hardener refuses to touch embedded secrets
node skills/workflow-hardener/scripts/harden-workflow.mjs examples/lead-intake.workflow.json --out /tmp/nope.json
# expected: exit 1, "Refusing to harden", nothing written

# 3) Harden the half-hardened workflow
node skills/workflow-hardener/scripts/harden-workflow.mjs examples/orders-sync.workflow.json --out /tmp/orders.hardened.json
# expected: 3 patches, score 85 → 100

# 4) Gate it in strict mode
node skills/workflow-hardener/scripts/verify-workflow.mjs /tmp/orders.hardened.json --strict
# expected: VERDICT: PASS, exit 0
```

## Scores and verdicts

`score = 100 − Σ weights` (critical 15, high 10, medium 5, low 2), clamped at 0.

| Score | Verdict | Meaning |
| --- | --- | --- |
| 95–100 | `production-ready` | No blocking or medium findings |
| 70–94 | `needs-hardening` | Medium findings remain |
| 0–69 | `not-production-ready` | At least one critical or high finding |

## What the hardener will and will not change

Applies: retry policy, HTTP timeout, execution order, pinned-data removal.

Never applies: credential values, webhook auth method, error-workflow target, duplicate-guard logic, node deletions, branch changes. Those are decisions, not transforms.

## Limitations — read before buying

- **Static analysis only.** The workflow was not imported into a live n8n instance during build, and `examples/` files were not executed. Import behavior for community nodes is untested.
- **n8n exports only.** Make.com and Zapier JSON use different schemas and are rejected.
- **Credentials are environment-specific.** A hardened file still needs its credentials reattached after import.
- **The score is a checklist, not a guarantee.** It measures the presence of known failure modes, not business correctness.
