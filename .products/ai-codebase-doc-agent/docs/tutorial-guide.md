# Tutorial Guide: AI Codebase Documentation Agent

**Goal:** From zero to documented codebase in under 5 minutes.  
**Time:** ~3 minutes for first successful run.  
**Skill level:** Any developer who can use a CLI.

---

## What You'll Build

By the end of this tutorial, you'll have:
- A polished README.md for your project
- An API reference document
- Architecture decision records capturing key design choices
- A developer onboarding guide

All generated from your codebase. All ready to commit.

---

## Step 1: Install the Agent

### Option A: Claude Code (Quickest)

```bash
# 1. Copy the skill to Claude's skill directory
cp -r skills/ai-codebase-doc-agent ~/.claude/skills/

# 2. Verify it's loaded
claude mcp list | grep doc-agent

# 3. Activate
claude
> "Document this codebase at path: /path/to/your/project"
```

### Option B: Cursor

```bash
# 1. Create the rules directory
mkdir -p /path/to/your/project/.cursor/rules/

# 2. Copy the SKILL.md
cp skills/ai-codebase-doc-agent/SKILL.md /path/to/your/project/.cursor/rules/ai-codebase-doc-agent.md

# 3. In Cursor Composer, type:
"Document this codebase"
```

### Option C: Any Other CLI Agent

```bash
# Copy the skill to your agent's skill root
# Then activate by describing the task
"I need you to document my codebase at /path/to/project"
```

## Step 2: Choose What To Document

The agent supports four doc types. You can enable all or pick specific ones:

| Doc Type | Description | Enabled by Default |
|----------|-------------|-------------------|
| `readme` | Project README with overview, setup, architecture | ✅ Yes |
| `api` | Functions, classes, endpoints, schemas | ✅ Yes |
| `adr` | Architecture Decision Records | ✅ Yes |
| `onboarding` | Developer onboarding guide | ✅ Yes |

To customize, tell the agent:
```
"Document this codebase at path: ./my-app, doc_types: readme,api"
```

---

## Step 3: Run Your First Documentation

Navigate to any codebase and activate the agent:

```
"Document this codebase at path: ./my-project, output: ./my-project/docs"
```

The agent will:
1. **Scan** your directory structure (~2-10 seconds for 100-500 files)
2. **Analyze** your architecture, detect languages, map modules (~10-30 seconds)
3. **Generate** all four doc types (~30 seconds to 2 minutes depending on codebase size)
4. **Report** what was generated with a summary

**You'll see output like:**

```
✅ DONE — All documentation generated

📄 docs/README.md
📄 docs/API-reference.md
📄 docs/ADR-001-initial-architecture.md
📄 docs/onboarding-guide.md
📄 docs/.doc-index.md

⚠️ 2 files skipped (contained potential credentials)
📝 Review each file for accuracy, then commit.
```

## Step 4: Review & Customize

Open the generated docs and verify:

```bash
# Check the README
cat docs/README.md

# Check API docs
cat docs/API-reference.md

# Check architecture decisions
cat docs/ADR-001-initial-architecture.md
```

**What to check:**
- Does the overview accurately describe the project?
- Are entry points and key modules correct?
- Do API signatures match the actual code?
- Are architecture decisions reasonable interpretations?

**How to iterate:**
```
"Re-generate just the README for this project, make it more detailed"
"Add another ADR explaining why we chose PostgreSQL"
"Regenerate the onboarding guide, target it at junior developers"
```

---

## Step 5: Commit

Once you're satisfied, commit the docs:

```bash
git add docs/
git commit -m "docs: add auto-generated codebase documentation"
```

Every generated document includes a footer:
> *AUTO-GENERATED BY AI CODEBASE DOC AGENT — VERIFY BEFORE COMMIT*

This reminds future readers that docs were AI-generated and should be verified.

## Advanced Usage

### Document Subdirectories

```bash
"Document only the src/ directory of this project"
"Document the tests/ directory, output: ./docs/testing-guide.md"
```

### Custom Output Location

```bash
"Document this codebase, output: ./documentation"
```

### Incremental Updates

```bash
# Agent detects existing docs, backs them up, regenerates
"Update the docs for this project — I've added a new API module"
```

### Style Customization

```bash
"Document this codebase with style: detailed"
"Document this codebase with style: minimal — just the README"
```

## Troubleshooting

| Problem | Solution |
|---------|----------|
| "No supported programming language detected" | Check your codebase has recognized file extensions (.js, .py, .rs, .go, .java, etc.) |
| Agent is slow on large codebases | Use `doc_types: readme` to generate just the essential docs |
| Generated docs feel generic | Use `style: detailed` and guide the agent with specific questions |
| Files with secrets are skipped | That's by design — move secrets to .env before documenting |
| Agent can't find my codebase path | Use absolute paths: `/Users/name/projects/my-app` |
