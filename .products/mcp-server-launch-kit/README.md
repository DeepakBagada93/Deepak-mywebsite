# MCP Server Launch Kit

Turn a tool spec into a runnable stdio MCP server, prove the protocol works, and block the release on security findings — in one pipeline.

## What it does

1. **Spec** — one `mcp.spec.json` defines tool names, descriptions, and JSON Schemas. Invalid specs are rejected, including destructive-sounding tools that do not warn about it.
2. **Scaffold** — generates a dependency-free Node server that speaks real MCP JSON-RPC over stdio: `initialize`, `tools/list`, `tools/call`, with required-argument and type validation.
3. **Prove** — a generated smoke test spawns the server and exercises the protocol. It must pass before any audit claim.
4. **Audit** — 13 static rules: hardcoded secrets and env fallbacks, secret logging, `eval`, shell execution, unauthenticated network listeners, filesystem writes, wildcard CORS, unbounded fetch, missing tests/README/engine, missing or invalid spec, missing input validation.
5. **Gate** — `verify-server.mjs` exits 1 on critical/high (or medium with `--strict`).

## Requirements

- Node.js 18+ (verified on Node 25.9.0)
- No dependencies, no API key, no network call. The generated server also has zero dependencies.

## First successful run (3 minutes)

```bash
cd mcp-server-launch-kit

# 1) Scaffold from the example spec
node skills/mcp-server-architect/scripts/scaffold-server.mjs \
  examples/repo-search.spec.json --out /tmp/repo-search-server

# 2) Prove the protocol works (spawns the server, initialize → tools/list → tools/call)
node /tmp/repo-search-server/test/smoke.test.mjs

# 3) Audit: expect 0 findings, 100/100
node skills/mcp-server-architect/scripts/audit-server.mjs /tmp/repo-search-server

# 4) Gate in strict mode: expect PASS, exit 0
node skills/mcp-server-architect/scripts/verify-server.mjs /tmp/repo-search-server --strict

# 5) See the blocking path
node skills/mcp-server-architect/scripts/audit-server.mjs examples/insecure-server   # 7 findings, 38/100
node skills/mcp-server-architect/scripts/verify-server.mjs examples/insecure-server  # exit 1
```

## Generated server behavior

- Transport: newline-delimited JSON-RPC 2.0 on stdio. No port, no network listener.
- Protocol version: `2024-11-05`.
- Methods: `initialize`, `notifications/initialized`, `ping`, `tools/list`, `tools/call`.
- Validation: required fields and primitive types are checked before the handler runs; violations return `isError: true` with details.
- Handlers: **dry-run echoes** (`{ tool, dryRun: true, received }`). Replace the body with real logic; keep the schema and validation.

## Limitations — read before buying

- **No real MCP client was connected during build.** The protocol is exercised by a generated smoke test over stdio, not by Claude Desktop, Cursor, or another host. See `COMPATIBILITY.md`.
- **Not the official SDK.** This is a minimal, dependency-free JSON-RPC implementation of the core methods. Features outside `initialize`/`tools/*` (resources, prompts, sampling, notifications beyond `initialized`) are not implemented.
- **Handlers are dry-run by default.** The kit guarantees contract, protocol, and security posture — not your business logic.
- **Static audit, not a penetration test.** Rules match known patterns; they are not a proof of security.
- **The score is a checklist.** It does not measure correctness or performance.
