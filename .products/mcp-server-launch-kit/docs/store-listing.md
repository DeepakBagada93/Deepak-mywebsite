## The problem

Shipping an MCP server is deceptively easy and quietly dangerous:

- Tool schemas exist in the code but nowhere reviewable, so clients get inconsistent contracts.
- Missing required-argument checks turn a bad call into a stack trace.
- A Bearer token is pasted into a request header "for local dev" and ships with the repo.
- A `run_command` tool does exactly what its name says, with no warning in the description.
- There is no test at all — the protocol was "tested" by opening it once.
- Nothing blocks the release, so the review happens after publication.

## What it does

1. **Validate the contract** — one `mcp.spec.json`; kebab-case name, semver, 1–20 tools, snake_case names, JSON Schemas, and a mandatory "destructive" warning on dangerous tools.
2. **Scaffold** — a dependency-free Node server implementing `initialize`, `tools/list`, and `tools/call` over newline-delimited JSON-RPC, with required-argument and type validation.
3. **Prove** — a generated smoke test spawns the server, initializes it, lists tools, asserts invalid arguments are rejected, and calls a tool successfully.
4. **Audit** — 13 static rules: secrets and env fallbacks, secret logging, `eval`, shell execution, unauthenticated listeners, filesystem writes, wildcard CORS, unbounded fetch, missing tests/README/engine, missing or invalid spec, missing validation.
5. **Gate** — `verify-server.mjs --strict` exits 1 on any critical, high, or medium finding.

## FAQ

**Does this use the official MCP SDK?**
No. It generates a dependency-free JSON-RPC implementation of the core tools methods (`initialize`, `tools/list`, `tools/call`) with protocol version `2024-11-05`. That is deliberate: no install step, no version drift, and it runs anywhere Node runs.

**Will it connect to Claude Desktop / Cursor / Claude Code?**
The protocol surface is implemented and smoke-tested over stdio, but **no real MCP host was connected during build**. `COMPATIBILITY.md` marks host connections `untested`. Treat the smoke test as protocol evidence, not host certification.

**Are the tools real?**
The generated handlers are explicit dry-run echoes (`dryRun: true`) so the server is immediately runnable and testable. You replace the handler body with your logic; the schema, validation, and protocol stay.

**Does it support resources, prompts, or sampling?**
No. Tools only. Those capabilities are out of scope for v1.

**Is the audit a security certification?**
No. It is a static pattern review across 13 rules. It does not prove the absence of vulnerabilities.

**Can I sell servers built with it?**
Yes. Generated output is yours, on every tier. Only reselling the kit's raw source is prohibited.
